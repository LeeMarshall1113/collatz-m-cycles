step whether it is **[Lean]** (kernel-checked in this repository), **[proved on paper]** (a proof is written down
here or in `computed/target7c_proofs/PROOFS.md`, and was checked by an independent AI referee, but is not

Contents: 0 overview and formalisation map; 1 setting; 2 chain inequalities; 3 rise bounds, Theorem 1 and Theorem

## 0. Overview

A positive Collatz cycle other than 1 -> 2 -> 1 with `m` local minima, `K` odd steps and period `p` must satisfy
bounds that tie `m`, `K`, and the size of its least element together (Hercher, Simons-de Weger). For each `m` this
leaves finitely many possible *shapes* `(K, p)`. Alick's idea: follow the `m` local minima around the cycle
(`n_0, n_1 = nextMin(n_0), ...`); their sizes `x_t = log2(n_t + 1)` can grow only so fast, because a long run of
odd steps (a *rise*) from an `N`-bit number is rare. If the minima cannot grow enough to supply the `K` odd steps
the shape needs, the shape is impossible.

* Alick bounded the total length `B2(N)` of **two** consecutive rises from an odd `n < 2^N`.
* We bound **three** rises, `B3(N)` (Theorem 1, Lemma 3S), and for m > 110 **four**, `B4(N)` (Theorem R).
  Longer windows give a stronger growth bound, so the same chain argument closes more shapes at larger `m`.

## 1. Setting and notation

`T(n) = n/2` (n even), `(3n+1)/2` (n odd). `delta = log2 3`. `T` extends to the 2-adic integers `Z_2` by the same
formula.

**Fact P** (Terras). For each `L >= 0`, `x -> (parities of x, T(x), ..., T^(L-1)(x))` induces a bijection
`Z/2^L -> {0,1}^L`. *Proof:* if `x = y (mod 2^(L+1))` they have the same parity and `T(x) = T(y) (mod 2^L)` (both
`(3x+1)/2` and `x/2` lose exactly one power of 2), which gives that the first `L+1` parities depend only on `x mod
2^(L+1)`; injectivity follows from the affine form of `T` on each parity class, surjectivity by counting. [Lean]
(`Terras.lean`, `ParityVector.lean`)

**Blocks.** An odd `n >= 1` has `n + 1 = 2^k a` with `a` odd. Then `T^j(n) + 1 = 3^j 2^(k-j) a` for `j <= k`, so
exactly `k` odd steps follow (the *rise* `k = orun n`), `T^k(n) = 3^k a - 1` is even, and exactly `l = v2(3^k a -
1) >= 1` even steps follow (the *descent* `l = erun n`), reaching the odd number `nextMin n = (3^k a - 1)/2^l`.
[Lean] (`block_eq`)

**Cycles.** Let a positive cycle have `m` local minima (odd elements with even predecessor), `K` odd steps in
total, period `p`, and least element `n_0`. Then `n_0` is a local minimum, and with `n_t = nextMin^t(n_0)`
(`t = 0..m-1`, once around the cycle) and `k_t = orun n_t`: `K = sum k_t` and `k_t <= x_t` since `2^(k_t)` divides
`n_t + 1`. Set `Lambda = p ln 2 - K ln 3 > 0`.

**External inputs.**
* E1 [external] (Barina): every `n <= 2^71` reaches 1, hence every element of a nontrivial cycle exceeds `2^71`.
* E2 [Lean] (Hercher Theorem 21, two-element form, `theorem21_two`): for a real `X` below every element and `1 <=
  m2 <= m`, `Lambda < (m - m2)/X + 1/(2^v - 1) + (m2 - 1)/(2^tau - 1)` with explicit `v, tau` depending on
  `m, m2, K`. Any integers `N <= v`, `M <= tau` may replace them.
* E3 [external] (Rhin via Simons-de Weger, `RhinBound`): `Lambda > exp(-13.3 (0.46057 + ln K))`.
* E4 [Lean] (Remark 7): `Lambda < m/X` (`ratioIn_of_crude`).

## 2. Chain inequalities

**Lemma 2.1 (one block)** [Lean, Alick]. For odd `n` with block `(k, l)` and `n' = nextMin n`:
`2^(k+1) (n'+1) <= 3^k (n+1) + 2^k`.
*Proof.* With `n+1 = 2^k a` and `2^l n' = 3^k a - 1`: `2^l [3^k a + 1 - 2(n'+1)] = (2^l - 2)(3^k a - 1) >= 0`, so
`2(n'+1) <= 3^k a + 1`; multiply by `2^k`.

**Lemma 2.2 (r blocks)** [r = 1, 2, 3: Lean; general r: proved on paper]. Let `n = m_0, m_1 = nextMin m_0, ..., m_r`
with rises `k_0..k_(r-1)`, `s_i = k_0 + .. + k_(i-1)`, `s = s_r`. Then

    2^r 2^s (m_r + 1) <= 3^s (n+1) + sum_{i<r} 2^i 3^(s - s_(i+1)) 2^(s_(i+1)).

*Proof.* Induction on `r`; the step multiplies Lemma 2.1 for `m_r -> m_(r+1)` by `2^r 2^(s_r)`, applies the
induction hypothesis (every term picks up a factor `3^(k_r)`) and adds the new term `2^r 2^(s_(r+1))`.

**Corollary 2.3.** Dividing by `3^s` and using `s_(i+1) >= i+1`, the error is at most `c_r = 2((4/3)^r - 1)`, so with
`x = log2(n+1)`, `x_r = log2(m_r+1)`:

    x_r <= x + (delta - 1) s - r + c_r / ((n+1) ln 2).

`c_2 = 14/9`, `c_3 = 74/27` (`(74/27)/ln 2 = 3.954 < 4`: **Lemma 3S**), `c_4 = 350/81` (`(350/81)/ln 2 = 6.23 < 7`).
For `n > 2^71` the error is below `2^-64` for every `r <= 13`, which is absorbed by the `2^-64` rounding slack of
the chain. The Lean statement of Lemma 3S is the integer inequality `8 * 2^s (n''' + 1) <= 3^s (n + 8)` and
`x''' <= x + (delta - 1) s - 3 + 14/(n+1)` (a slightly cruder constant than 4; also below the slack for `n > 2^71`).

**Lemma 20 (Hercher)** [Lean]: `x_t <= delta x_(t-1)`.

`s` is the total rise over the `r` blocks. If `n < 2^N` then `s <= B_r(N)`, where

    B_r(N) = max { k_0 + .. + k_(r-1) : n odd, n < 2^N }

is the *r-rise bound*. A small `B_r(N)` bounds the growth over `r` steps by `(delta-1) B_r(N) - r` instead of
`(delta-1) * (sum of x) ...`; that is the whole gain.

## 3. Computing the rise bounds: Theorem 1 and Theorem R

`B_r(N)` is a maximum over all odd `n < 2^N`. Directly that is 2^N numbers, but only run lengths matter.

Let `u_k = (2/3)^k in Z_2`, so `v2(u_k) = k`. For `x in Z_2` that is not a non-negative integer `< 2^N`, let
`z_N(x)` be the least `i >= N` such that bit `i` of `x` is 1.

**Theorem 1 (exact 2-adic form of B3)** [proved on paper; not in Lean]. For `sigma = (k0, l0, k1, l1) in Z_(>=1)^4`
put `K = k0 + k1`, `lambda = l0 + l1`, `P2 = K + lambda` and

    nu(sigma) = -1 + u_(k0) (1 - 2^(l0)) + 2^(l0) u_K (1 - 2^(l1))  in Z_2.

Then `B3(N) = max { z_N(nu(sigma)) - lambda : sigma, z_N(nu(sigma)) > P2 }`, and the maximum is attained.

*Lemma 1.1.* The parity vector of `nu(sigma)` is `1^(k0) 0^(l0) 1^(k1) 0^(l1) 1^infty`.
*Proof.* `nu + 1 = 2^(k0) a` with `a = 3^(-k0) c` odd, where `c = (1 - 2^(l0)) + 2^(l0) u_(k1)(1 - 2^(l1))` is odd
because `l0, k1 >= 1`. As in the integer case `T^j(nu) + 1 = 3^j 2^(k0-j) a`, so exactly `k0` odd steps occur, ending
at `c - 1 = 2^(l0) (-1 + u_(k1)(1 - 2^(l1)))`; the bracket is odd, so exactly `l0` even steps follow, reaching `nu_1
= -1 + u_(k1)(1 - 2^(l1))`. The same computation for `(k1, l1)` gives `k1` odd steps to `-2^(l1)`, then `l1` even
steps to `-1`, a fixed point of `T` that is odd, so the parities continue `1^infty`.

*Lemma 1.2.* For `j >= 1` and odd `n`: `n` has runs `(k0, l0, k1, l1) = sigma` and `k2 >= j` iff `n = nu(sigma) (mod
2^(P2+j))`. *Proof.* The condition says the first `P2 + j` parities are `1^(k0)0^(l0)1^(k1)0^(l1)1^j`; the trailing
`1^j` (j >= 1) pins down the last descent. By Lemma 1.1 `nu` has this prefix, and by Fact P exactly one class mod
`2^(P2+j)` does.

*Lemma 1.3.* A class `C mod 2^L` containing the odd 2-adic `nu` meets `{1, 3, .., 2^N - 1}` iff `L <= z_N(nu)`.
*Proof.* If `L <= N`, the representative `nu mod 2^L` is odd and below `2^N`, and `z_N(nu) >= N >= L`. If `L > N`
the class meets `[0, 2^N)` iff its least representative `nu mod 2^L < 2^N`, iff bits `N..L-1` of `nu` vanish, iff
`z_N(nu) >= L`. `z_N(nu)` is finite: otherwise `nu` would be a positive integer whose parity vector ends in
`1^infty`, so `v2(nu+1) = infty`, impossible.

*Proof of Theorem 1.* Fix `sigma`. By Lemmas 1.2 and 1.3, the largest `k2` achievable by an odd `n < 2^N` with runs
`sigma` is `j*(sigma) = z_N(nu) - P2` (such `n` exist iff `j* >= 1`, because every odd `n` has `k2 >= 1`); the best
total is `K + j* = z_N(nu) - lambda`. Every odd `n < 2^N` has some `sigma`, so `B3(N)` is at most the maximum, and
every feasible `sigma` is realised by an actual `n < 2^N`. The set of totals is bounded, so the maximum exists. []

**Theorem R (r rises)** [proved on paper]. For `r >= 2` and `sigma = (k0, l0, .., k_(r-2), l_(r-2))` put `K_i = k0 +
.. + k_i`, `Lambda_i = l0 + .. + l_(i-1)`, `lambda = Lambda_(r-1)`, `P = K_(r-2) + lambda` and

    nu_r(sigma) = -1 + sum_{i=0}^{r-2} 2^(Lambda_i) u_(K_i) (1 - 2^(l_i)).

Then the parity vector of `nu_r(sigma)` is `1^(k0) 0^(l0) .. 1^(k_(r-2)) 0^(l_(r-2)) 1^infty` and `B_r(N) = max
{ z_N(nu_r(sigma)) - lambda : z_N(nu_r(sigma)) > P }`. *Proof:* induction on `r`, peeling `k0` odd steps and `l0`
even steps exactly as in Lemma 1.1, then Lemmas 1.2-1.3 verbatim with `P` in place of `P2`. (`r = 2` is `B2(N) =
max { z_N(alpha) - l0 : z_N(alpha) > k0 + l0 }` with `alpha = -1 + u_(k0)(1 - 2^(l0))`.)

**How the grids are computed** [computed]. The four-parameter (B3) and six-parameter (B4) searches are turned into
*joins* (`b3join.py`, `b4join.py`): writing `nu = X(k0, l0) + 2^(l0) W(K, l1)` (B3), the bits of `nu` in a window
above position `N` must vanish, which is a condition "low bits of `P + Q + carry` are zero" on a pair of lists of
about `N^2` entries each (sorted by bit-reversed key); false matches are filtered exactly, every borrow/carry is
decided by exact window scans, and **every reported maximiser is re-simulated literally with the Collatz map**. The
result is exact once the best value found is at least `N + t - 1` for the cutoff `t` used (otherwise the run is
repeated with smaller `t`). Costs: B3(38,243) about 50 min on a loaded machine; B4(852) about 30 min on 4 threads
(the join is paged per `K1` so the hit buffer is bounded, `b4join.py`).

## 4. The chain theorem

**Theorem 3.1** [proved on paper; Lean `mOK3_sound` for r <= 3]. Let `(K, p)` be the shape of a hypothetical cycle
with `m` minima. Let `g_r` be finite tables with `B_r(N) <= g_r(N)` at their grid points `N`, and
`b_r(y) = min { g_r(N) : N >= ceil(y) }` (a *suffix minimum*, so no monotonicity of `B_r` is assumed; a term is
dropped if the set is empty). Define rationals `Y_0, .., Y_(m-1)`:
* `Y_0 >= log2 ceil(Ub)` where `Ub = (m - m2)/(Lambda_lo - tail)` for an admissible `m2`, `Lambda_lo <= Lambda`
  certified, and `tail` the two later terms of E2;
* `Y_t >= min { D Y_(t-1),  Y_(t-2) + (D-1) b2(Y_(t-2)) - 2 + 6/2^71,  Y_(t-3) + (D-1) b3(Y_(t-3)) - 3 + 4/2^71,
  [r=4:] Y_(t-4) + (D-1) b4(Y_(t-4)) - 4 + 7/2^71 }` with `D >= delta`.

If `sum Y_t < K`, no such cycle exists.

*Proof.* The least element `n_0` is a local minimum (if it were even, `n_0/2` would be smaller; if its predecessor
`q` were odd, `n_0 = (3q+1)/2 > q`). With `x_t = log2(n_t + 1)`, `sum x_t >= K` (section 1). By E2 with `X = n_0`,
`n_0 < Ub`, so `x_0 <= Y_0`. Induct on `t` assuming `x_j <= Y_j` for `j < t`: Lemma 20 gives `x_t <= delta x_(t-1)`;
if `N >= ceil(Y_(t-2))` is a grid point then `n_(t-2) < 2^N`, so `k_(t-2) + k_(t-1) <= B2(N) <= g2(N)` and the
two-step lemma (with `n_(t-2) > 2^71`) gives `x_t <= Y_(t-2) + (delta-1) g2(N) - 2 + 6/2^71`; three- and four-step
cases are the same with Corollary 2.3. So `x_t` is at most each candidate, hence at most their minimum `Y_t`. The
windows `t-r..t` never wrap around the cycle, so no cyclic argument is needed. Finally `K <= sum x_t <= sum Y_t <
K`, a contradiction. []

**Implementation.** The Lean version works in `2^-64` fixed-point units with rounding always in the safe direction;
the `2^-64` slack absorbs the `6/2^71, 4/2^71, 7/2^71` terms. The Python version (`chain3.py`, `chainr.py`) uses
exact `Fraction` arithmetic with mpmath interval bounds for `log2`, rounds up, and compares `sum Y_t` with `K` as
exact rationals. The *ratio* quoted throughout is `sum Y_t / K`; a shape is closed if it is `< 1`.

## 5. Shapes, the Rhin ceiling and the hard shape

For each `m` the possible shapes are found as follows.

1. `0 < p - K delta < Lambda/ln 2` (E4, `Lambda > 0`), so `p = ceil(K delta)`: a shape is determined by `K`.
2. **Rhin ceiling.** E2 with `m2 = m` gives `Lambda < m 2^(2 - K/G(m))`; with E3 this excludes every `K` above an
   explicit `Kceil(m)` (found by interval bisection above the point where the exponent is monotone).
3. **Strip and filter.** The remaining `K` below `Kceil` lie in the Remark-7 strip; the Theorem-21 filter (a
   conservative test using rational bounds on `delta`, a cap on `N, M`, and a minimum over `m2`) keeps the
   *survivors*. The enumeration is done by lattice/continued-fraction methods (`fastshapes.py`, Lean: the Farey walk
   `MCycleWalk.lean`).
4. Each survivor is run through Theorem 3.1.

Candidate counts: 2,303 at m = 110 (Lean data), 334,036 survivors at m = 121, 5,291,301 candidates (5,291,294
survivors) at m = 127; the count grows by a factor of about 1.585 per `m`.

**The hard shape** is `K = 27,444,133,206,411,171,953` (a convergent denominator of `delta`). It is the worst shape
for every `m >= 110`; its ratio grows by a factor of about 1.58 per `m` (one extra `delta`-step at the end of the
chain), so with a fixed set of grids it fails at some `m`. The grids determine where:

| grids | closed for all shapes up to | worst ratio at the last `m` |
|---|---|---|
| Alick: `B2` to N = 23,446 | m = 101 | 0.798 (K = q41 = 77,692,117,359,936,589,403) |
| `B2` to 66,903 | 103 | 0.8246 |
| `B2` to 1,039,710 plus `B3` to 38,243 | **121** | **0.996289**; m = 122 fails (1.579) |
| plus `B4` to 852 | **127** | **0.996295** (0.9962878 with the full 117-point snapshot); m = 128 fails (1.579) |
| **Lean**: `B2` to 647,476, `B3` at {79, 122, 203, 325} | **110** | 0.9897 (all 2,303 shapes, Lean arithmetic mirrored in `check110.py`) |

The Lean grids are deliberately minimal: only the points the m <= 110 chains use. The margins are thin (0.9897 at
110 in Lean; 0.37% at 127).

## 6. The Lean checkers

### 6.1 `AllTriples` (three-rise bound) [Lean]

For `n` odd with `n < 2^N` write `n + 1 = a 2^(k0)` (`a` odd, `a < 2^A`, `A = N - k0`), and let `l0, l1 >= 1` be the
next two descents, `k1, k2` the next rises, `a1, a2` the odd parts:

    3^(k0) a + 2^(l0) = 2^(l0 + k1) a1 + 1,      3^(k1) a1 + 2^(l1) = 2^(l1 + k2) a2 + 1.

`TripleCond N B k0` says every such solution has `k0 + k1 + k2 <= B`; `AllTriples N B` says this for every `k0 in
[1, N]`; `threeRiseBound_of_allTriples` derives `ThreeRiseBound N B` from it by unfolding `block_eq` three times.
With `c0 = 3^(-k0)`, `c = 3^(-(k0 + k1))` modulo `2^W`, `p = l0 + k1`, `q = p + l1`, one has `a = y - c 2^q (mod
2^(min(W, q + k2)))` with `y = c0 (1 - 2^(l0)) + c 2^p`. If `k0 + k1 + k2 > B` then `k2 >= E = max 1 (B + 1 - k0 -
k1)`, so the bits `A..q + E - 1` of `y - c 2^q` vanish. For each triple `(k0, l0, k1)` (finitely many: `l0` and `l0
+ k1` are bounded by the lowest set bit `>= A` of the running 2-adic value) the checker refutes this for every `q`
at once: *direct tests* (a W-bit mask/shift computation `dOK`) for the few `q` where a match is possible, and a
bit-parallel *window search* (`matchMask`) over all `q < A` that finds the candidates. Everything is natural-number
arithmetic with `Nat.land/shiftRight/mod/div`, evaluated by the kernel (GMP-backed) via `decide +kernel`, with
soundness proved once (`rangeOK3_sound`, `dOK_sound`, `testBit_matchMask`, ...). `AllTriples 79 88`, `122 135`,
`203 216` and `325 340` are checked; the last is split by `l0` range (`ThreeRiseSplit.lean`). Cost: about 0.8 ms of
kernel time per triple, `~N^3/6` triples, so B3(325) is about 80 minutes and B3(522) about 5.5 hours; the cost
explodes for the grid points needed beyond m = 113.

### 6.2 The linear-time two-rise checker [Lean]

Alick's `AllPairs N B` (two-rise bound) checks the pair equations `3^(k0) a + 2^l = 2^(l + k1) a1 + 1` in the same way
over all `k0`. Its Lean implementation stalled for `N = 97,951` (6.7 hours at 6.5 GB without finishing; the cause was
module size and dense candidate lists at small `k0`, not the mathematics). `TwoRiseCheck2.lean` checks the same
`TwoRise.RangeCond` using only linear-time kernel operations:

* `dOK`: the direct test via masks and shifts, `(c mod 2^j + 2^j - (c mod 2^d) 2^l) mod 2^j >= 2^A`; `val_eq` proves
  it equal to the old product/division form and `dOK_sound` gives `directOK`;
* window candidates carry their exponent (a bisection guess, then a check `p2 i = Pt`);
* `smallOK`: first rises `k0` with `3^(k0) 2^N <= 2^(B+2) - 2^(k0+1)` are closed by size alone (`k0 <= 10` for `B - N =
  14`), which removes the dense small-`k0` cases;
* the window is `E1 = B - N + 6` bits instead of 16, so false candidates are rare;
* a downward loop `c -> 3c mod 2^W` (an add, a shift and a mask) from a verified start value
  (`rangeOK2_sound`).

Cost about 1.9 ms per first rise at `N = 97,951`, 3.9 ms at 247,533, about 9 ms at 647,476 (old checker 10.4 ms at
97,951). `TwoRiseCheck3.lean` (`kOK2x`) fixes a residual blow-up: at `N = 384,012` a first rise whose window has its
lowest set bit close to the top matches almost no bits and produced ~22,000 candidates in one declaration (13 GB);
`kOK2x` sends such rises (about 1 in 128) to a window 32 bits wider, with soundness inherited from `kOK2`. Grids are
split into modules of ~16,000 first rises, each peaking at ~2 GB.

### 6.3 Walks and certificates [Lean]

For each `m` the Farey walk of the strip is checked in pieces (`WalkSplit.lean`; the `MCycle1xxWalk*` modules, joined
by split lemmas whose soundness reduces to Alick's `mOK_sound`), then one certificate per surviving shape checks the
chain of Theorem 3.1 in fixed-point arithmetic (`MCycle1xxCerts*`, `mOK3_sound`). Modules are generated by
`research/scripts/mcycle10*/gen*.py`; the generators are not trusted, only the kernel's re-check of their output.
Cost about 3.3 s per shape. `main_statement_110` is the conjunction of these with `hX` and `RhinBound`.

## 7. The four-rise extension to m <= 127 [computed; not in Lean]

* **B4.** `B4(N)` via Theorem R with `r = 4` (`b4join.py`: `~(N+64)^4/24` probes, paged per `K1`). Validation: equal
  to brute force for `N = 4..22` (value and the set of near-maximisers, including a run forcing the paging path);
  re-computation of 31 of the 36 older points: 0 mismatches. Every maximiser is re-simulated.
* **Grid.** 117 exact points `N = 72..852` (`b4_grid_snapshot_le852.json`), including 70 *adaptive* points: the chain
  looks up `b4(Y)` at the next grid point `>= Y`, wasting up to ~5% of `N`; for the 12 least-`K` hard shapes
  `adapt.py` logs every `N = ceil(Y_(t-4))` asked for and computes the missing exact `B4(N)`. Without them `m = 126`
  fails (1.008).
* **Chain.** `run11.py`/`fastchain.py`: Theorem 3.1 with the four-term minimum, over all shapes. `fastchain` first
  screens each candidate with a cheap monotone upper bound on the ratio (valid by monotonicity of the chain in `Y_0`);

## 9. Weak points and what is not claimed

* **m <= 127 is not formally verified.** It rests on Python tables of `B2, B3, B4` that were each computed by one
  implementation and re-computed by another, but not proved sound in Lean. The `B_r` values enter the chain as
  *upper bounds*; a computed value that is too small would make the argument unsound. Overstated values are safe.
* **Thin margin.** Worst ratio 0.9963 at m = 121 and 127 (0.37% below 1). A uniform +4 on every `B3` value would
  already break m = 121 (ratio 1.008), +7 gives 1.598; `B2` tolerates about +1000. Individual binding points tolerate
  errors of +14 or more, and two independent `B3` implementations agree exactly on all used points.
* **Theorem R for r = 4 and the r-step chain lemma** were proved by the generating session and used by the referee
  for the claims it recomputed; the referee verified the `r = 4` error constant and the algorithm against brute force
  for `N <= 22`, but did not write an independent written proof of Theorem R. Theorem 1 (`r = 3`) was independently
  proved and re-derived.
* **Shape completeness** in Python (m > 110) relies on the enumerator and filter, with two independent
  implementations agreeing up to m = 121 and one independent count at m = 127. In Lean, completeness is the Farey
  walk's soundness theorem.
* `fastshapes.py` uses floats to bound `lam_bound` on each `K` interval (with a `1e-9` inflation) before the exact
  test; safe, but load-bearing in principle (G2).
* `grid_own.json` `B2` values are upper bounds, not exact values (1-2 too large at 14 small `N`); harmless.
* On Python 3.14 with `gmpy2`, set `MPMATH_NOGMPY=1` (mpmath hands `mpz` to `Fraction`).
* Inputs `hX` (Barina) and `RhinBound` are assumed, not verified here; the Lean statement carries them as hypotheses.
* This does not touch the Collatz conjecture itself.
